03 / Technical challenges

The hard parts,
and how I solved them.

Each challenge follows the same structure: the problem, what I did about it, and what it changed.

01

Keeping the app usable with no network

Offline-first Sync Expo

The problem

The app is mostly used on the go. Every write went straight to the server, so a dropped connection meant a spinner, then lost progress.

What I did

Writes go to a local queue first and the UI updates optimistically. The queue is replayed in order when the connection returns, with per-field timestamps to settle conflicts.

Result

Every screen works offline. Sync is invisible to the user, and no progress has been lost since the queue shipped.

02

Securing data without writing a custom API

Supabase PostgreSQL RLS

The problem

The client talks to the database almost directly. One missing rule and any signed-in user could read someone else's rows.

What I did

Row Level Security on every table, denied by default. Each policy is covered by a test that signs in as two different users and checks what each one can see.

Result

Access rules are versioned as migrations, reviewed like code, and verified in CI before each release.

03

Testing business logic without a simulator

Vitest TypeScript CI

The problem

Rules were mixed into React components. Testing one meant booting a device, and regressions slipped through between releases.

What I did

Moved every rule into a pure TypeScript domain layer with no Expo imports. Components only call it; Vitest runs it in Node.

Result

The full suite runs in under four seconds on each push, so refactoring the UI no longer risks the logic.
